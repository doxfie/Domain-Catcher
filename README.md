# Domain Catcher

![OpenWrt](https://img.shields.io/badge/OpenWrt-BusyBox%20ash-00B5E2)
![Dependencies](https://img.shields.io/badge/dependencies-tcpdump--mini%20%2B%20nft-orange)
![Version](https://img.shields.io/badge/version-0.6.1--beta-blue)

SSH-утилита для OpenWrt: показывает, к каким доменам обращается устройство в сети,
чтобы добавить их в правила раздельной маршрутизации - PassWall2, Podkop, NetShift
или любого другого прокси-клиента. Домены берутся из двух источников сразу:

- **DNS** - лог запросов `dnsmasq`;
- **SNI** - имя сервера из TLS ClientHello, снятое с LAN-интерфейса.

---

## 🚀 Установка

```sh
wget -O /usr/bin/.dcatch.new https://raw.githubusercontent.com/doxfie/Domain-Catcher/main/domain-catcher.sh && tail -n1 /usr/bin/.dcatch.new | grep -qx '# DCATCH-EOF' && chmod +x /usr/bin/.dcatch.new && mv /usr/bin/.dcatch.new /usr/bin/dcatch && dcatch
```

Установка нужна один раз. Дальше утилита запускается командой `dcatch` - она же
открывает меню при каждом следующем запуске.

---

## 🕸 Зачем SNI

`dnsmasq` видит запрос, только если клиент спросил роутер. Часто он не спрашивает:

| Ситуация | DNS-лог | SNI |
|---|:---:|:---:|
| Ответ закеширован, идёт по сохранённому IP | ❌ | ✅ |
| Свой DoH (`8.8.8.8`, `1.1.1.1` по :443) | ❌ | ✅ |
| Свой DoT (:853) | ❌ | ✅ |
| IP зашит в прошивку | ❌ | ✅ |
| Обычный запрос через роутер | ✅ | ✅ |

Имя хоста уходит открытым текстом внутри самого TLS-соединения, поэтому SNI виден
там, где DNS-лога нет. В логе у каждой строки указан источник.

## 🎛 Использование

Отметьте клиента, встаньте на «Начать сбор доменов» и нажмите `Enter`. Настраивать
ничего не нужно, текущие параметры видны на том же экране:

```text
   Источник:  DNS + SNI
   Правила:   перехват DNS, блок DoT, блок QUIC

Клиенты
   [ ] Все клиенты
   [x] 192.168.1.141   TCL-65C6K   68:c8:c0:b4:10:ed   10h 30m
   ...

Действия
 > Начать сбор доменов
   Настройки сбора
   Назад
```

Во время сбора **выполните на устройстве то, что хотите поймать** - откройте
приложение, нажмите проверку обновлений, запустите воспроизведение. Без этого
нужного трафика не возникнет.

Сбор останавливается **любой клавишей**, `Ctrl+C` тоже работает. В меню: `↑`/`↓` -
выбор, `Space` - отметить клиента, `Enter` - подтвердить, `q` - назад.

### Временные правила

На время сбора поднимается отдельная nft-таблица `inet dcatch_capture`:

- **перехват DNS** - `redirect` порта 53 клиента на роутер, ловит хардкод вроде `8.8.8.8`;
- **блок DoT** - закрывает :853;
- **блок QUIC** - закрывает udp:443, иначе ClientHello зашифрован и SNI не прочитать.

`fw4`, PassWall2, Podkop и `zapret` она не задевает и снимается сама - при остановке
сбора, по `Ctrl+C` и при выходе. Если всё же осталась: `nft delete table inet dcatch_capture`.

Отключить правила можно в «Настройках сбора», там же выбор одного источника.

## 🔐 Статус TLS

У каждого домена из SNI видно, чем закончилось рукопожатие, - так сразу понятно,
какие домены режутся и их пора отправлять в туннель:

```text
TIME     CLIENT_IP       SRC       TLS    DOMAIN
-------- --------------- --------- ------ ----------------------------------------
18:54:22 192.168.1.130   dns/A            www.google.com
18:54:22 192.168.1.130   dns/AAAA         www.google.com
18:54:22 192.168.1.130   sni       ok     www.google.com
18:54:22 192.168.1.130   sni       ok*    rutracker.org
18:54:26 192.168.1.130   sni       drop   blocked.example
```

| Статус | Что произошло |
|---|---|
| `ok` | сервер ответил ServerHello - рукопожатие прошло |
| `drop` | ответа нет 5 секунд - типичная блокировка по SNI, реже лежит сервер |
| `rst` | соединение сброшено вместо ответа |
| `tspu?` | сброс, похожий на подмену: пришёл быстрее, чем мог ответить сервер, или с чужим TTL |
| `alert` | сервер отказал TLS-алертом - неизвестное имя, неподходящая версия TLS |
| `fin` | сервер закрыл соединение, ничего не ответив |
| `abort` | клиент сам закрыл соединение, не дождавшись ответа, - это не блокировка |
| `-` | сбор остановили раньше, чем пришёл ответ |

**Звёздочка** - соединение принял прокси на самом роутере (PassWall2, Podkop и
другие с прозрачным проксированием). Тогда статус показывает путь через туннель, а
не напрямую, а `tspu?` не ставится: подмену снаружи отсюда не видно. Роутер узнаётся
по TTL: его пакеты уходят в LAN с TTL ровно 64, от внешнего сервера после форварда
приходит не больше 63.

Для `tspu?` утилита снимает SYN и SYN-ACK на :443: из них время до сервера и TTL
его пакетов. Без них - если соединение открылось до начала сбора - сброс остаётся
просто `rst`.

Строка SNI появляется, когда исход известен: обычно через доли секунды, для `drop`
через 5 секунд. Порог задаётся переменной:

```sh
DCATCH_TLS_TIMEOUT=10 dcatch
```

После сбора под списком доменов выводятся **рукопожатия с проблемами** - домены,
у которых хоть одно соединение не прошло, со счётом по исходам.

## 📝 Лог

`/tmp/domain-catcher.log`, формат `HH:MM:SS IP DOMAIN SRC [TLS VIA]`, где `SRC` -
`sni` или `dns/<тип записи>`: `dns/A`, `dns/AAAA`, `dns/HTTPS` и так далее. Один
домен обычно запрашивается сразу несколькими типами, поэтому строк DNS на него
несколько. Колонка клиента при этом показывает адрес, с которого пришёл запрос, а
не версию запрошенного адреса. У строк SNI ещё два поля: `TLS` - статус из таблицы выше
(подмена записана как `tspu`), `VIA` - `router`, `direct` или `-`. Домен
по-прежнему третье поле. `dnsmasq logqueries` включается только на время сбора и
возвращается в исходное состояние.

## 🔄 Обновления

При запуске, но не чаще раза в сутки, скрипт сверяется с **последним релизом** на
GitHub и обновляет `tcpdump-mini`. Новая версия ставится и перезапускается сама,
фонового процесса нет, без интернета проверка пропускается.

Сверка идёт по тегу релиза, а не по ветке `main`. Команда установки выше берёт файл
из `main`, поэтому свежая установка может оказаться новее релиза - тогда обновления
просто не будет, откат не делается.

`tcpdump` нужен для SNI, поэтому при первом запуске ставится `tcpdump-mini`
(~385 КБ). Если поставить не удалось, скрипт не запускается: тихо отдать
неполный список хуже, чем отказать. Когда пакета нет в принципе - например,
репозиторий вашей версии OpenWrt уехал в архив, - остаётся сбор только по DNS:

```sh
DCATCH_SOURCE=dns dcatch
```

## 🌐 IPv6

Учитывается наравне с IPv4: устройства предпочитают IPv6, когда он есть, и без
этого часть доменов просто не попадала бы в список.

Клиент отбирается **по MAC**, а не по адресу - одно правило покрывает обе версии
протокола и все временные адреса, которые privacy extensions плодят десятками и
меняют на ходу. MAC берётся из `/tmp/dhcp.leases`; если у какого-то клиента его
там нет, для него одного отбор идёт по адресу.

Адреса нужны лишь фильтру DNS-лога - в логе `dnsmasq` есть только IP клиента.
Список IPv6 собирается из таблицы соседей (`ip -6 neigh`), она покрывает и SLAAC,
и приватные адреса.

## ⚙️ Требования

OpenWrt с BusyBox `ash` - для стрелочного меню нужна поддержка `read -s -n 1`.
Остальное из базовой поставки: `awk`, `ip`, `uci`, `nft`, `logread`, `wget`.
`tcpdump-mini` ставится сам.

Проверено на OpenWrt 25.12.5 (mediatek/filogic) рядом с PassWall2 26.8.27 (xray 26.7.28)
и zapret, раньше - с Podkop 0.7.21.

## ⚠️ Ограничения

- SNI не виден при **ECH** (Encrypted ClientHello).
- Очень крупный ClientHello может не поместиться в один TCP-сегмент - такой домен пропускается.
- IPv6-пакеты с extension headers не разбираются: ожидается TCP сразу за основным заголовком.
- Адрес, созданный устройством уже во время сбора, не попадёт в фильтр DNS-лога -
  но домен всё равно будет пойман по SNI, там отбор идёт по MAC.
- В режиме «все клиенты» исключаются собственные адреса роутера.
- Статус TLS - про рукопожатие, а не про всё соединение: блокировку, которая режет
  трафик уже после ServerHello (заморозка на ~16 КБ), он не покажет - будет `ok`.
- `tspu?` - эвристика по времени и TTL. Сервер за балансировщиком, который сбрасывает
  соединение сам, может выглядеть так же.
- Если прокси на роутере перехватывает весь TCP, а не только список доменов, всё
  будет со звёздочкой: напрямую из LAN тогда не ходит ничего, и статус показывает
  итог для клиента.
